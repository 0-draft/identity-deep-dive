# 相互運用チェックリスト

- [ ] テスト鍵がシードから導出でき、公開の JWK と一致する。3 つの WIT が発行者の鍵で検証に通る（Section 3）。
- [ ] 値を使う前に RFC 8792 の折り返しを外す。バックスラッシュ、改行、次の行の先頭の空白を取り除く（Section 2）。
- [ ] 各署名ベースの `workload-identity-token` の行には、印刷されたプレースホルダーではなく WIT の全文を入れる。そうしたときだけ P-01 が再現できる（Section 2、検証ログ）。
- [ ] P-01 から P-06 で、署名ベースとリテラルの Signature 値がバイト単位で再現でき、検証者が T0+60 で受理する（Section 4）。
- [ ] `@query` は先頭の `?` を含み、クエリがなければ `?` だけになる（P-01、P-05。RFC 9421 Section 2.2.7）。
- [ ] CONNECT の `@authority` は既定ポートを省いた `svcb.example.com` になる（P-04。RFC 9421 Section 2.2.3。基底 -09 Section 3）。-08 の文言どおりに `:443` を残す実装は P-04 に失敗する。
- [ ] ES256 の署名は r||s をそのまま連結した形で、RFC 6979 の nonce で作るので、署名し直した値がバイト単位で一致する（P-03、Section 2）。
- [ ] 検証者は WIMSE の署名をタグで選び、囮を無視し、WIMSE タグが二つあるメッセージを拒否する（P-06、N-08、N-22）。
- [ ] 検証者は、署名が有効でも、必須のコンポーネントやパラメーターが欠けていれば拒否する（N-01、N-05、N-11）。`keyid`、`alg`、CONNECT のカバー範囲という送信者向けの規則を強制するかどうかも記録する（N-02、N-06、N-07、N-21）。
- [ ] Content-Digest のない本文は拒否する（N-03）。Content-Digest と合わない本文はダイジェストの検査で拒否する。Section 5.4 の記述にかかわらず、N-04 では署名自体は検証に通る。
- [ ] 有効期間は端を含む。P-01 は T0+300 で受理し、WIT-A がまだ有効な T0+301 で拒否する（N-09b）。T0+3600 の N-09 は WIT-A の `exp` にも当たる。
- [ ] `wimse-aud` は、設定された集合と Simple String Comparison で照合するので、末尾のスラッシュは拒否される（N-10）。
- [ ] クライアントは、`wimse-req-nonce` がない、または値が違う署名付きレスポンス（N-12、N-13）と、`wimse-sign-response` を付けたリクエストへの署名なしレスポンス（N-14）を拒否する。
- [ ] 鍵とアルゴリズムは `cnf.jwk` からだけ取る。N-15 は svcC の鍵では検証に通っても拒否する（Section 5.16）。
- [ ] 無効な WIT と無効な署名には、同じ問題タイプの同じ 400 レスポンスを返し、401 は返さない（N-17）。基底 Section 3.6 では本文は SHOULD なので、problem details の本文のない 400 を合格とするかをテスト環境で決めておく。
- [ ] 署名しなければならないのにできないサーバーは、501 の `wimse-signed-response-unsupported` か 400 の `wimse-signed-response-unavailable` を返し、署名なしの 200 は返さない（N-18）。
- [ ] クライアントの Accept-Signature は、少なくとも基底 Section 3 のレスポンスのコンポーネントを挙げる（N-19）。
- [ ] WIT が期限切れで署名は有効なメッセージは、副作用なしで拒否される。これで WIT が先に検査されていることがわかる（N-20）。WIT の検証手順は workload credentials ドラフトの Section 5.1.3 にある（-09 の文言）。-08 の「Section 5.1.4」はそのドラフトに存在しない。
- [ ] 送信者の nonce は 64 ビット以上のエントロピーを持つ。Section 5.17 は N を決めていないので、ハーネスは何件のリクエストを集めるかを明記する（N-16）。
- [ ] 結果は基底のリビジョンを明記して記録する。セットは -08 を引用しているので、基底が変わったら引用された要件を確かめ直す。
