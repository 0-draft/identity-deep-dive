# Interop Checklist

- [ ] The SD-JWT header has `typ` set to `dc+sd-jwt`, and a media type, where one is used, is `application/dc+sd-jwt` (Sections 2.1 and 2.2.1).
- [ ] `vct` is a case-sensitive string that is a Collision-Resistant Name, and `vct`, `iss`, `exp`, `nbf`, `cnf`, `vct#integrity`, `aka_vcts` and `status` are never inside a Disclosure (Sections 2.2.2.1 and 2.2.2.3).
- [ ] `aka_vcts` is a non-empty array of Collision-Resistant Names that does not contain the `vct` value. For type matching a Holder or Verifier treats the credential as being of the `vct` type and of each `aka_vcts` type (no BCP 14 keyword since -25), and does not read `aka_vcts` as proof that the Issuer may issue that type (Sections 2.2.2.2 and 7.7).
- [ ] A credential with `cnf` but neither `sub` nor `iss` is accepted. Since -24 the draft updates RFC 7800 and nullifies the `sub`/`iss` requirement of its Section 3 for SD-JWT VCs, SD-JWTs and JWTs, so a JWT library that enforces that rule must not apply it here (Section 2.2.2.3.1).
- [ ] A credential without selectively disclosable claims has no `_sd` claim and no Disclosures (Section 2.2.2.5).
- [ ] When Key Binding is required, the KB-JWT is verified with the `cnf` key (Section 2.4).
- [ ] When `status` is present it is checked (SHOULD). A Verifier that skips the check cannot detect revocation or suspension and accepts that risk according to its policy (Section 2.4, since -25).
- [ ] A credential carrying both an HTTPS `iss` and an `x5c` header is verified with the mechanism that the Verifier's policy selects for that Issuer, not one chosen by the credential, and an attacker cannot influence which verification process is used (Sections 2.5 and 7.3). Inputs of the other mechanism are not treated as identifying the Issuer unless policy binds them (for example through a Subject Alternative Name or a configured mapping) and the binding has been verified (Section 2.5, since -24).
- [ ] With `x5c`, the chain is validated per RFC 7515 Section 4.1.6 and RFC 5280 against a trust anchor permitted for the Issuer, and no certificate in `x5c` is used as a trust anchor merely because it is there. `x5c` is read from the protected header, the Issuer is the end-entity certificate subject, and an `iss` is not authenticated by this mechanism: a recipient MAY reject an `iss` not bound to the certificate, and an Issuer SHOULD NOT send one without such a binding (Section 2.5).
- [ ] The well-known URL for `iss` values with and without a path matches the examples, and any terminating `/` is removed before the URL is built (Section 4.1). An Issuer does not use an `iss` with a query, a fragment or dot-segments in the path, and lowercases its scheme and host (RECOMMENDED since -24) (Section 4); the draft does not say how a recipient treats a non-conforming one.
- [ ] The issuer metadata `issuer` is identical to the `iss` value, and the data is not used otherwise. Exactly one of `jwks` and `jwks_uri` is present (Sections 4.2 and 4.3).
- [ ] Every dereferenced URL and every redirect target is HTTPS (data: URIs allowed only for rendering resources), the number of redirects is limited, and 4xx and 5xx responses are never used as content (Section 3).
- [ ] Loopback, link-local, private-use and other addresses that the IANA IPv4 and IPv6 Special-Purpose Address Registries mark as not globally reachable, internal host names and DNS names that resolve to internal addresses are refused before any request (Section 7.1). -26 has no exception for destinations allowed by local policy.
- [ ] Each retrieval is time-bound and size-bound, and the content is validated against its expected format before use (Section 3).
- [ ] The retrieved Type Metadata `vct` equals the reference used to fetch it, for the initial document and for each `extends` parent (Section 5.3).
- [ ] A `#integrity` value is a valid SRI integrity metadata string, the strongest supported hash is used, a mismatch or an unsupported algorithm rejects the document, and CORS headers play no role (Section 6).
- [ ] A document cached by integrity value may be reused regardless of `no-store`, and one cached without an integrity value follows RFC 9111 (Section 5.3.4).
- [ ] An `extends` cycle is detected and rejected (Section 7.4).
- [ ] A child type does not change `sd` from `always` or `never` to another value, or `mandatory` from true to false, and a `display` property in the child replaces rather than merges (Sections 5.5.2, 5.6.5 and 5.6.5.1).
- [ ] Claim `path` handling follows Section 5.6.1.2: a string on a non-object, or null or an integer on a non-array, is an error, while a missing key or index only removes the element.
- [ ] A verifier does not reject a presentation because a selectively disclosable mandatory claim is absent, and array positions count undisclosed elements (Section 5.6).
- [ ] A malformed `claims` array, or a `path`, `mandatory` or `sd` that does not conform, causes rejection, while a bad `display` or `svg_id` does not (Sections 5.6 and 5.7).
- [ ] When policy requires Type Metadata and it cannot be retrieved or processed, the credential is rejected (Section 5.7).
- [ ] An SVG template is not rendered (SHOULD) when a placeholder's `svg_id` is missing from claim metadata, when a claim value contains invalid XML characters, or when the `path` behind an `svg_id` selects more than one value, and `svg_id` never appears with a `path` that contains null (MUST NOT). Values are escaped for at least `&`, `<`, `>`, `"` and `'`, placeholders appear only in text content, no code in the template is executed, and the SVG display is sandboxed if that cannot be prevented reliably (Sections 5.5.1.2.2, 5.6 and 7.10).
- [ ] Remote key references in `cnf` (`x5u`, `jku`, URL `kid`) are not followed. The draft advises against them and says only confirmation methods without remote retrieval SHOULD be supported (Section 8.3).
- [ ] Servers send `X-Content-Type-Options: nosniff` and a restrictive `Content-Security-Policy` for metadata and rendering resources (SHOULD, Section 7.2).
- [ ] Test vectors are taken from -26. The examples changed in -24 and -25, and -26 has the same examples as -25.
